# Ndosi Profile Picture Automation

Automated UI and API test suite validating the profile picture upload
functionality on the Ndosi Simplified Automation practice site, built with
Python, Playwright, and pytest. Runs on a daily schedule via GitHub Actions.

## Overview

This project automates and validates two things:

1. **UI flow**: Login → Menu → My Profile → Edit Profile → Upload Picture →
   Save → Verify the update actually completed
2. **API validation**: Every network endpoint hit during that UI flow is
   captured and its response status code is validated

The two suites are connected — the UI test captures real network traffic
during the browser flow and writes it to `test_data/captured_endpoints.json`,
which the API suite then reads and validates against.

## Tech Stack

- **Python 3.12**
- **Playwright** — UI browser automation
- **pytest** — test runner
- **Allure** — HTML test reporting
- **GitHub Actions** — CI/CD, scheduled daily

## Setup (local development)

```powershell
pip install -r requirements.txt
python -m playwright install
```

Create a `.env` file in the project root (this is gitignored and never committed):

NDOSI_BASE_URL=https://ndosisimplifiedautomation.vercel.app
NDOSI_USERNAME=your_test_username
NDOSI_PASSWORD=your_test_password


## Running Tests Locally

Run the UI test first — this generates the screenshots and the captured
endpoints file the API suite depends on:

```powershell
python -m pytest tests/ui -v -s
```

Then run the API suite:

```powershell
python -m pytest tests/api -v
```

Add `--headed` to the UI command to watch the browser run instead of headless.

## CI/CD

Tests run automatically **every day at 00:00 SAST** (22:00 UTC) via GitHub
Actions, defined in `.github/workflows/daily-tests.yml`. The workflow can
also be triggered manually from the **Actions** tab (`workflow_dispatch`).

### Required GitHub repo secrets

| Secret name        | Value                                              |
|---------------------|-----------------------------------------------------|
| `NDOSI_BASE_URL`    | `https://ndosisimplifiedautomation.vercel.app`      |
| `NDOSI_USERNAME`    | test account email                                  |
| `NDOSI_PASSWORD`    | test account password                               |

Set these under **Settings → Secrets and variables → Actions** in the repo.

### Pipeline steps

1. Checkout code
2. Set up Python 3.12
3. Install dependencies + Playwright browsers
4. Run UI tests (captures screenshots + network traffic)
5. Run API tests (validates captured endpoint status codes)
6. Generate Allure report
7. Upload `screenshots/` and `reports/allure-report/` as pipeline artifacts

## Test Coverage

### UI flow tested

1. Login with valid credentials
2. Open the navigation menu
3. Navigate to My Profile
4. Click Edit Profile
5. Select a new profile picture via the file chooser
6. Save changes
7. Explicitly wait for and verify the upload API call returns `200 OK`
   before considering the test passed

### API endpoints validated

| Endpoint | Method | Purpose |
|---|---|---|
| `/APIDEV/login` | POST | Authenticates the user |
| `/APIDEV/groups` | GET | Loaded on app init |
| `/APIDEV/profile` | GET | Fetches profile data |
| `/APIDEV/my-enrollments` | GET | Dashboard data |
| `/APIDEV/my-instructor-tasks` | GET | Dashboard data |
| `/APIDEV/my-instructors/today` | GET | Dashboard data |
| `/APIDEV/my-testimonials` | GET | Profile page data |
| `/APIDEV/profile` | PUT | Updates profile |
| `/APIDEV/profile/image` | POST | **Profile picture upload — core endpoint under test** |
| `/APIDEV/student/today` | GET | See Known Issues below |

Each endpoint is validated as its own individually named pytest test case,
so pass/fail status is visible per-endpoint in both the terminal output and
the Allure report, not just as a single bulk assertion.

## Known Issues Found

- **`GET /APIDEV/student/today` returns `404`** on every run observed so far.
  This is tracked explicitly in `tests/api/test_endpoints.py` as a known
  issue (`xfail`) rather than silently ignored or hidden — if this endpoint
  starts returning a different status, the test suite will flag it as a
  changed/new issue rather than continuing to pass silently.

## Reports

Allure reports are generated after every run and uploaded as a GitHub
Actions artifact. To view a downloaded report locally:

```powershell
cd path\to\allure-report
python -m http.server 8000
```

Then open `http://localhost:8000` in a browser. (Opening `index.html`
directly by double-clicking it will not work — Allure's report is a
single-page app that loads its data via `fetch()`, which browsers block on
`file://` URLs for security reasons.)

## Screenshots

Screenshots are captured at each step of the UI flow and uploaded as a
pipeline artifact on every run:

1. After login
2. After opening the menu
3. On the My Profile page
4. On the Edit Profile page
5. After selecting the new photo
6. After the save/upload completes and is confirmed via the API response

## Architecture Notes

- **Page Object Model** — `pages/` contains one class per page/section of
  the app (`LoginPage`, `MenuPage`, `ProfilePage`), keeping selectors out of
  the test files and making the suite easier to maintain as the UI changes.
- **Upload verification, not just click-and-hope** — the upload step doesn't
  just click "Save Changes" and assume success. It uses Playwright's
  `expect_response()` to wait for and capture the actual
  `POST /profile/image` network response, then asserts its status code.
  This was a deliberate fix after an early CI run showed the test passing
  even though the upload had not actually completed in time — a timing
  difference between local headed runs and headless CI execution. Verifying
  the real network response, rather than relying on UI-only signals, closes
  that gap.
